# Подготовка Linux VM: границы ответственности

Этот документ — общие ориентиры, а не отчёт о конкретном сервере.
AttackScope не устанавливает обновления ОС и не меняет SSH, firewall или другие
приложения автоматически. Перед системными работами оператор составляет свой
план, создаёт приватные backup и проверяет путь восстановления доступа.

- Устанавливайте поддерживаемые ОС и container runtime из доверенных источников.
- Проверяйте актуальные security advisories для фактических версий.
- Защитите Docker API: доступ к нему равнозначен высоким привилегиям на host.
- UI оставляйте на localhost или приватном Unix socket; используйте SSH-туннель.
- Внешний ingestion требует TLS и отдельных source credentials.
- Изменение SSH-аутентификации требует резервного доступа и проверки новой сессии.
- Не переносите системные UID/GID, пути и правила другого сервера без проверки.

Успешный health-check приложения не доказывает отсутствие компрометации VM.
Операции обновления host, смены credentials и расследование других сервисов
не входят в приложение. Примеры: [VM_DEPLOYMENT.md](VM_DEPLOYMENT.md),
[PRODUCTION.md](PRODUCTION.md), [SECURITY.md](SECURITY.md).
