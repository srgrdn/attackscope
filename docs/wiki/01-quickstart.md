# 01. Первый запуск и навигация

[Вики](README.md) · [Далее: Timeline](02-timeline.md)

## Результат этого раздела

Вы откроете нужную установку, убедитесь, что backend доступен, загрузите учебные
события при локальном запуске и узнаете назначение основных экранов.

## Если приложение уже работает

1. Откройте `http://localhost:8180` для обычного локального экземпляра.
2. Для VM, настроенной по примеру, используйте `http://localhost:18180` при активном
   SSH-туннеле. Инструкция подключения — [VM_DEPLOYMENT.md](../VM_DEPLOYMENT.md).
3. После обновления frontend один раз перезагрузите вкладку, при необходимости
   с обходом cache браузера.
4. Проверьте **«Backend подключён»**. Это проверка готовности API и базы,
   а не проверка полноты сбора со всех серверов.
5. Откройте Timeline, выберите **24h** и посмотрите список VM.

Поля времени подписаны UTC. Внешний вид календаря зависит от браузера и ОС:
на снимках возможны американский порядок месяца/дня и 12-часовой формат AM/PM.
Это формат отображения поля, а не переключение временной зоны.

При отсутствии туннеля браузер не сможет подключиться к VM через локальный адрес.
Не подменяйте адрес на публичный IP: UI по умолчанию не публикуется в Интернет.

## Новый локальный запуск

Нужны Docker Engine и Compose v2. Python, Node и зависимости приложения
используются внутри образов; устанавливать их на host для обычного запуска не нужно.
Команды выполняются из корня полученного репозитория:

```sh
docker compose config --quiet
docker compose up --build --wait
docker compose exec backend python -m attackscope.demo --run-name morning --scenario investigation
```

Откройте `http://localhost:8180`. Демо-команда создаёт отдельный host `demo-morning`
и 2086 синтетических наблюдений. Запросы к чужим серверам она не делает.
После загрузки классификация продолжается в фоне: дайте очереди обработаться.

При первом запуске скачиваются pinned образы и зависимости. Сборка потребляет
больше ресурсов, чем уже работающие контейнеры; фиксированного обещания времени
сборки или памяти на произвольном VPS нет.

Основная локальная БД хранится в Docker volume. Обычный `docker compose down`
сохраняет данные. Удаление volumes не является шагом перезапуска.

### Если демо уже запускалось

Повтор с тем же `--run-name` идемпотентен и сохраняет прежнее базовое время.
Он не переносит старые события к текущему моменту. Сначала расширьте период.
Для отдельного свежего набора выберите другое имя:

```sh
docker compose exec backend python -m attackscope.demo --run-name training --scenario investigation
```

Появится `demo-training`; прежняя VM и данные останутся. Не загружайте demo в
рабочую production-базу для устранения пустого экрана.

## Как открыть именно данные из скриншотов

Для вики подготовлены ещё семь записей: шесть cloud/config probes и одна
помеченная операторская проверка. Их нет в обычном наборе `investigation`.
Они загружаются только в отдельный временный стенд документации:

```sh
python3 scripts/docs_screenshots.py --keep-running
```

После успешного завершения откройте `http://localhost:18182`.
На стенде один host `demo-wiki`, 2093 события и подготовленные правила.
Подробности запуска и остановки — [11. Обновление скриншотов](11-screenshots.md).
Нужен host Python 3.9+ для этого вспомогательного инструмента; браузер запускается
в отдельном Playwright-контейнере. Это не требование основного runtime.

## Основная навигация

| Экран | Когда его открывать |
|---|---|
| Event Timeline | Найти момент, всплеск, последовательность и интересующий IP |
| IP Explorer | Собрать историю одного адреса в выбранном периоде |
| Event Explorer | Работать с отдельными строками, фильтрами и выгрузкой |
| Overview | Сравнить общий объём и число классифицированных событий |
| История до 365d | Изучить почасовую динамику, когда детали уже недоступны |

Кнопка состояния backend выполняет повторную проверку подключения. Она не
переподключает Vector, не создаёт новые источники и не исправляет журналы VM.

## Время в интерфейсе

Шкала, поля **«С (UTC)»**, **«До (UTC)»** и показываемые timestamps относятся к UTC.
Введите время именно в UTC, даже если браузер или ОС используют другой часовой пояс.
Например, при вашем смещении UTC+8 местным 16:00 соответствует 08:00 UTC.

Предустановки **1h / 24h / 7d / 30d** отсчитываются от текущего времени интерфейса.
Они не привязываются к последнему найденному событию.

## Контрольная проверка

- Backend подключён.
- В списке VM виден ожидаемый host.
- Диапазон включает время события или загрузки demo.
- При выборе одной VM меняются данные её наблюдений.
- Можно открыть Event Explorer и карточку события.

Если один из пунктов не выполняется, переходите к [диагностике](09-troubleshooting.md),
сохраняя существующие данные и конфигурацию.
