# 10. Поля, термины и ограничения

[Вики](README.md) · [Назад: диагностика](09-troubleshooting.md) · [Далее: скриншоты](11-screenshots.md)

## Основные понятия

| Термин | Значение |
|---|---|
| Host / VM | Зарегистрированный сервер, которому привязаны source credentials |
| Source | Канал доставки определённого kind: ssh, http, firewall |
| Event | Сохранённое нормализованное наблюдение |
| Finding | Объяснимое срабатывание правила с evidence |
| Evidence | Ссылки на исходные события, обосновывающие finding |
| Bucket | Временная ячейка с фактическим количеством наблюдений |
| Rollup | Сохранённый агрегат времени/IP/host/category/port |
| Detail retention | Срок доступности отдельных events и их полей |
| Deduplication | Недобавление записи при повторе стабильной ссылки в пределах TTL |
| Ingestion | Аутентифицированный приём batch событий backend |
| Backpressure | Ограничение доставки при занятости/переполнении, вместо бесконечного роста памяти |

## Нормализованная модель события

Необязательные неизвестные значения остаются `null` или отсутствуют в проекции.
Не заменяйте неизвестное нулём, пустым «фактом» или предположением.

| Поле | Смысл |
|---|---|
| id | Идентификатор сохранённого события |
| schema_version | Версия event schema; текущая — 1 |
| timestamp | Время наблюдения из источника, UTC |
| received_at | Время приёма backend, UTC |
| host_id | Сервер аутентифицированного источника |
| source | ssh / http / firewall |
| event_type | Конкретный тип, например http.request или ssh.auth_success |
| category | Более общая группа, например http_request |
| severity | info / low / medium / high |
| src_ip / dst_ip | Известные адреса источника/назначения |
| src_port / dst_port | Известные порты источника/назначения |
| protocol | Протокол, когда определён |
| classification | Указатель на последнее совпавшее правило/finding |
| attributes | Безопасные поля конкретного источника |
| source_reference | Стабильная ссылка исходной записи для replay/dedup |
| safe_original | Разрешённая очищенная проекция, не raw log |

Поддержаны IPv4 и IPv6. IPv4-mapped IPv6 канонизируется к IPv4. Zone-scoped
адреса не являются поддержанным способом указать публичный source IP.
Точный контракт и transport envelope — [DATA_MODEL.md](../DATA_MODEL.md),
[INGESTION.md](../INGESTION.md), [API.md](../API.md).

## Время и задержка

`timestamp` используется для временной карты и rule windows. `received_at`
показывает, когда backend принял запись. При очереди или поздней доставке
между ними может быть заметная разница. Это не автоматически длительность атаки.

`duration_ms` — длительность HTTP-запроса по доступным данным producer. Это не
разница timestamp/received_at и не системная загрузка VM.

Внутреннее хранение UTC не отменяет необходимость правильно читать локальный
часовой пояс оператора. В формах AttackScope указывается UTC.

## Адреса и порты

Source port клиента часто меняется между соединениями. Его множество само
по себе не означает сканирование разных портов сервера. Для port_probing
используются **destination** ports наблюдаемых firewall events.

Не всякий HTTP remote_addr — исходный внешний пользователь: возможны NAT,
reverse proxy и Docker gateway. X-Forwarded-For — недоверенное утверждение
без отдельно настроенной цепочки trusted proxy.

## Повторная доставка

Идемпотентность строится по source и стабильному source_reference.
Повтор с тем же действующим ключом не создаёт ещё одно event и не увеличивает
rollup counters. Для SSH/journal producer может использовать hash cursor,
для Nginx — server-generated request_id.

Если стабильного ID нет, произвольный hash содержимого не гарантирует
различение двух одинаковых настоящих запросов. Система не обещает вечный dedup:
delivery keys по умолчанию хранятся 30 дней. Подробности replay после TTL и
истечения detail — [RETENTION.md](../RETENTION.md).

## Ограничения интерфейса и API

| Область | Значение по умолчанию / поведение |
|---|---|
| Detail time range | До 30 дней и внутри доступного detail retention |
| History | До 365 дней, только полные UTC часы |
| Event Explorer page | До 100 записей |
| Cursor | 15 минут |
| Export | До 10 000 событий / 8 MiB, иначе 413 |
| Findings list | До 500, с явным truncated |
| Evidence IDs | До 100, actual count отдельно |
| Matched paths | До 20, truncation явно |
| Distribution tables | Top 100, truncation явно |
| HTTP path | До 2048 UTF-8 bytes; producer может пометить обрезку |
| Сохранённый User-Agent | До 512 UTF-8 bytes после очистки backend |
| Сохранённый username | До 128 UTF-8 bytes после очистки |
| Attributes / safe projection | Ограничены размером, не бесконечные raw blobs |
| Стандартный ingestion body | До 1 MiB; batch до 500 событий |

Пределы могут быть конфигурируемыми; проверьте свою `.env` и образ. Production
Vector использует более маленькие пачки, чем максимум backend. Пределы страницы,
экспорта и агрегатов — разные механизмы.

## Когда обновляются данные

Timeline и findings используют polling примерно раз в 30 секунд для своего
текущего запроса. Readiness проверяется примерно раз в 15 секунд.
Классификация и retention работают фоновыми workers.

Фиксированный диапазон не превращается в автоматически сдвигающееся окно:
чтобы включить более позднее время, заново выберите 1h/24h либо задайте «До».
Остальные страницы обновляются через смену параметров, переход/перезагрузку
или собственные доступные кнопки. WebSocket в v0.1 не требуется.

## Безопасное чтение наблюдений

User-Agent, path, hostname и другие строки приходят из недоверенных журналов.
В UI они выводятся текстом. Сохраняется ограниченная проекция без HTTP secrets.
Но username/IP/path всё равно могут раскрывать внутренние сведения.

Нельзя из одного текста заключить об исполнении команды, SQLi/XSS success,
личности источника или полной безопасности сервера. Для подтверждения нужны
соответствующие дополнительные источники и проверка контекста.

## Границы v0.1

AttackScope не заменяет полноценный IDS/IPS/SIEM или мониторинг CPU/RAM/Disk.
Нет автоматических блокировок, AI-подтверждения атак, массового пересчёта
истории при смене правил, multi-user UI login и встроенного offsite backup.

Полнота анализа ограничена тем, что реально пишет источник, удалось прочитать,
нормализовать, доставить и сохранить. Отсутствующие наблюдения не заполняются
выдуманными деталями. Ограничения времени, окон и retention необходимо включать
в выводы расследования.
